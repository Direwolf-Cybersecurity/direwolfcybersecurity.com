# Legal requirements checklist

**Prepared:** 2026-10-23 for Direwolf Cybersecurity. Companion to `docs/legal-research.md`
(the research and sources; section numbers below cite it as "research §n") and
`docs/claims-register.md` (approved wording for every claim). Not legal advice: every item
marked _Attorney_ is a question for counsel, and every legal page is a draft for attorney
review until the launch runbook's legal-review gate closes.

**How to read the status column**

| Status          | Meaning                                                                       |
| --------------- | ----------------------------------------------------------------------------- |
| `Drafted`       | Written into the website or this repo; awaiting attorney review               |
| `Platform`      | Must be implemented in the platform repo (`direwolf-platform`); spec provided |
| `Owner`         | Needs a fact or decision only Mitch can supply                                |
| `Attorney`      | Needs counsel's judgment or sign-off                                          |
| `N/A at launch` | Checked; does not apply yet; revisit trigger noted                            |

## 4. Consent and acknowledgement (what the platform sign-up and login must show)

This section is the implementation brief for PLAN.md §14.4. The exact recommended texts are in
`docs/platform-consent-spec.md`; this section states the requirements they satisfy. Sources:
research §2 (_Nguyen_, _Meyer_, _Berman_, _Oberstein_, _Chabolla_; E-SIGN; Colorado UETA),
§3 (NIST SP 800-171 3.1.9, NIST SP 800-53 AC-8), §4.4, §4.10, §5.2.

### 4.1 Sign-up (account creation)

| #     | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Status     |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------- |
| 4.1.1 | **Clickwrap, not browsewrap or sign-in-wrap.** An **unchecked** checkbox the user must check, placed between the last form field and the submit button, on the same screen, above the fold at 375 px width. Never pre-checked.                                                                                                                                                                                                                                           | `Platform` |
| 4.1.2 | **Checkbox A label:** "I have read and agree to the Direwolf Cybersecurity **Terms of Service** (v2026.10.24.2), **Acceptable Use Policy** (v2026.10.24.2) and **Privacy Policy** (v2026.10.24.2)." Each document name is a real hyperlink (underlined, link color, 4.5:1 contrast) to the versioned document at `www.direwolfcybersecurity.com/legal/{terms,acceptable-use,privacy}/`, opening in a new tab. The version numbers are displayed on screen.               | `Platform` |
| 4.1.3 | **Checkbox B label (prohibited-data attestation), separate and unchecked:** "I understand that the Direwolf Platform is not approved for Controlled Unclassified Information (CUI), export-controlled technical data (ITAR/EAR), protected health information (PHI), payment card numbers or classified information, and I will not upload or configure the services to collect any of these unless Direwolf has agreed in writing that the service is approved for it." | `Platform` |
| 4.1.4 | **Authority line** under the checkboxes: "By creating this account you confirm that you are at least 18 years old and authorized to bind [organization name] to these terms." Collect the signer's title in a form field.                                                                                                                                                                                                                                                | `Platform` |
| 4.1.5 | **Button text references the act:** "Create account and accept terms". Disabled until both boxes are checked; on a forced submit, show the error text next to the unchecked box. Never "Continue" or "Next".                                                                                                                                                                                                                                                             | `Platform` |
| 4.1.6 | **Separate consents.** Any marketing opt-in is its own optional, unchecked box; never bundled with the terms (CAN-SPAM; Stripe's promotional-consent rule). Not offered at launch.                                                                                                                                                                                                                                                                                       | `Platform` |
| 4.1.7 | **Readable.** Same font size as labels, normal contrast, no gray-on-gray; real `<label for>`; errors via `aria-describedby`; keyboard-operable; visible focus.                                                                                                                                                                                                                                                                                                           | `Platform` |
| 4.1.8 | **Records.** On submit, one append-only `ConsentRecord` per document (`terms`, `aup`, `privacy`, `prohibited-data`) with user, org, version, SHA-256 of the document text, server UTC time, IP, user agent, locale, `method = signup_checkbox`, UI build id.                                                                                                                                                                                                             | `Platform` |
| 4.1.9 | **Evidence.** A dated screenshot of the sign-up screen (desktop and 375 px) for every UI change and every document version, kept with compliance evidence.                                                                                                                                                                                                                                                                                                               | `Platform` |
